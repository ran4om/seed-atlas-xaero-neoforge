# Seed Atlas for Xaero's World Map (1.21.1 NeoForge)

[![Build](https://github.com/ran4om/seed-atlas-xaero-neoforge/actions/workflows/build.yml/badge.svg)](https://github.com/ran4om/seed-atlas-xaero-neoforge/actions/workflows/build.yml)

An unofficial port of [DUzzL/seed-atlas-xaero](https://github.com/DUzzL/seed-atlas-xaero) to
Minecraft 1.21.1 and NeoForge 21.1. It draws the biomes, terrain and structures that a world seed
generates into Xaero's World Map, around the terrain you have actually explored.

It is a client-side mod. Servers do not need it, and players without it can still join.

## Requirements

- Minecraft 1.21.1, NeoForge 21.1.x (tested on 21.1.257), Java 21
- Xaero's World Map 1.47.0 or newer (it brings its XaeroLib dependency)
- Windows x86-64, Linux x86-64, or macOS (Intel or Apple silicon)

Xaero's Minimap, XaeroPlus, Sodium and ImmediatelyFast work alongside it.

Website: https://ran4om.github.io/seed-atlas-xaero-neoforge/

## Download

Get the jar from [Releases](https://github.com/ran4om/seed-atlas-xaero-neoforge/releases). Every
push to `main` also builds one, attached to its run on the
[Build](https://github.com/ran4om/seed-atlas-xaero-neoforge/actions/workflows/build.yml) workflow.

## Install

1. Install NeoForge 21.1 for Minecraft 1.21.1 and Xaero's World Map 1.47.0 or newer.
2. Put `seedatlas-xaero-2.0.1-mc1.21.1-neoforge.jar` in the `mods` folder.

Only the players who want the seed map need it. Do not install it on a server.

Singleplayer worlds are detected automatically. On a server the client cannot read the seed, so run
`/seedatlas seed <seed>` once; the seed is remembered for that server.

## Use

Open Xaero's World Map. The seed layer fills everything you have not explored yet. The `SA` button
on the map opens the settings, where you can switch on structure markers, choose which structures to
show, and change opacity and performance options.

Client commands:

| Command | Effect |
| --- | --- |
| `/seedatlas` or `/seedatlas status` | Shows the seed, version, layer and engine state |
| `/seedatlas seed <seed>` | Sets the seed for the current world or server (text seeds are hashed like vanilla) |
| `/seedatlas dimension-seed <nether\|end> <seed>` | Gives one dimension its own seed |
| `/seedatlas clear [nether\|end]` | Forgets the seed |
| `/seedatlas version [auto\|<version>]` | Predicts an older world generation (for worlds made before 1.21) |
| `/seedatlas settings` | Opens the settings screen |

## Limits

- Only vanilla generation is predicted. Structures added by mods or datapacks are not shown, and
  vanilla structures that a datapack moves or removes can show in the wrong place.
- Markers show where a structure can generate. Its final placement can still fail in game, and
  approximate positions are marked as such in the map UI.
- Upstream refines terrain heights and Nether cave floors with the batched density API of Minecraft
  26.x. 1.21.1 has no such API, so this port uses the native engine's heights. Shading is a little
  coarser and Nether carvers are not masked.

## How it was checked

`./gradlew build` compiles the mod and runs every test:

- `test` runs inside NeoForge (FML JUnit) and compares the bundled engine with 1.21.1's own
  generator for four seeds:
  - 1500 random block biomes per dimension.
  - Every stronghold within 20,000 blocks, generated by vanilla's own ring code.
  - Village placement.
  - Concurrent native calls.
- The `*Test` tasks are upstream's standalone suites, ported to this build: config persistence,
  icon layout, biome highlight, command registration, and a bytecode check that the installed Xaero
  build still has every method the mixins target.

`./gradlew runHarness` starts a real client with a development-only harness mod (`src/devHarness`,
never in the jar). It creates a seeded world, runs the commands, opens the map in all three
dimensions, saves screenshots to `run-harness/screenshots` and quits.
`-PharnessMods=<dir>` loads extra mod jars as well, for compatibility runs.

## Releasing

Set `mod_version` in `gradle.properties`, add a section for it to [CHANGELOG.md](CHANGELOG.md),
then push a matching tag (`git tag v2.0.1 && git push origin v2.0.1`). The Release workflow builds
and tests the jar and publishes a GitHub release with the changelog section as its notes.

## Website

The project site is plain HTML and CSS in `site/`, with screenshots taken by `runHarness`. The
Website workflow publishes it to GitHub Pages whenever `site/` changes on `main`.

## Native engine

The engine is C (Seed Atlas, derived from cubiomes) and is bundled for each platform under
`src/main/resources/natives`. Java calls it through JNA. To rebuild it:

```sh
cmake -S native -B build/native -DCMAKE_BUILD_TYPE=Release && cmake --build build/native && ctest --test-dir build/native
ZIG=/path/to/zig sh native/build-cross.sh build/native src/main/resources/natives   # zig 0.13.0
```

`build-cross.sh` builds all four bundled libraries with zig. The Linux one targets glibc 2.17, so it
loads on older distributions than the one it was built on.

The CMake build patches two places where the pinned engine differs from vanilla 1.21.1. Both are
covered by the parity test:

- **End biome borders.** The engine's End voronoi used block y as a cell index and misplaced
  about 3% of End blocks next to biome borders. End block biomes now go through the same
  `voronoiAccess3D` path as the overworld and the Nether.
- **Stronghold biomes.** The engine counted cherry groves as stronghold biomes, but 1.21.1's
  `stronghold_biased_to` tag leaves them out, so a few strongholds moved by several chunks.
